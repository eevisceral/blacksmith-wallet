Blacksmith

Your smart account

A Kernel account on Ethereum and Base. The Kernel is a smart contract that holds the assets. Connect the wallet that owns it. The assets are not in that wallet.

The account

The wallet you connect is the owner, and the only key. Each chain has its own Kernel, its own balance, and its own deployment. The address matches on Ethereum and Base when both use this page's factory. If a row shows another address, pay that one on that chain. Anyone can send to the address shown for a chain before you create the Kernel there. Create once on a chain to send from it. The owner wallet pays that transaction.

Blacksmith V1 is this Kernel. Connect the same wallet and the balances on that chain are here. This page never has the key. If the wallet is lost, the account cannot be recovered here.

This copy is not served from the contract. The Kernel is still on the chain. Save this page stores a file you can open later.

A usual Ethereum account is an address controlled by one key. Account abstraction makes the account a contract. That contract holds the assets. The key stays in the owner wallet, a different address. ERC-4337 is the Ethereum standard for this. The contract here is a Kernel. A send is a UserOp. The owner signs it, and the EntryPoint (v0.6), a shared contract, checks the signature and runs the send.

You see the Kernel for that owner on the chain selected in the header. Each chain shows whether its Kernel is created, how much ETH it holds, and the address when that address differs. Tokens and activity follow the header. If it already has code, you can send. If it does not, Create Kernel deploys it. That is a normal transaction from the owner wallet, and that wallet pays the network fee. Funds already at the address shown for this chain are already in that Kernel. Create Kernel stays off when the owner wallet has no ETH on this chain, when a transaction is still confirming, or when the factory for new accounts is not on this chain yet. A Kernel that already exists still opens.
